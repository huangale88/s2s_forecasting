# Subseasonal-to-Seasonal (S2S) Forecasting

This repository contains a PyTorch-based machine learning pipeline for Subseasonal-to-Seasonal (S2S) forecasting. The project is designed to handle multi-dimensional meteorological and hydrological data—including gridded weather data (ERA5), meteorological forcings (Daymet), and static basin attributes (CAMELS). It uses Hydra for robust and scalable configuration management.

## Quick Start

### Installation

1. Clone the repository:
   ```bash
   git clone https://github.com/huangale88/s2s_forecasting.git
   cd s2s_forecasting
   ```

2. Create and activate the Conda environment:
   ```bash
   conda env create -f environment.yml
   conda activate s2s_forecast
   ```

### Running the Code

To execute the training pipeline using the default configuration (currently configured to use generated dummy data and a baseline linear model):

```bash
python scripts/train.py
```

To override specific configurations dynamically via the command line using Hydra:
```bash
python scripts/train.py training.epochs=10 model.hidden_dim=256
```

## Repository Structure and Data Flow

The codebase is organized to separate configuration, execution scripts, and core modular source code. 

### 1. Configurations (`configs/`)
Hydra is used for compositional configuration. At runtime, Hydra reads `config.yaml` and merges the specified sub-configurations.
* `config.yaml`: The master configuration file linking data, model, and training parameters.
* `data/dummy.yaml`: Defines tensor dimensions, sequence lengths, batch size, and the number of variables for datasets.
* `model/dummy_linear.yaml`: Hyperparameters for the baseline S2S model.
* `training/default.yaml`: Training hyperparameters including learning rate, epochs, and compute device.

### 2. Execution Scripts (`scripts/`)
These are the primary entry points for interacting with the pipeline.
* `train.py`: The main training script. It initializes Hydra, instantiates data loaders and the model, sets up the optimizer and loss function, and executes the training loop.
* `evaluate.py`: A placeholder script intended for loading trained model checkpoints and running evaluations against test data.

### 3. Core Source Code (`src/`)
This directory contains the primary Python packages for the pipeline.
* **`engine.py`**: Contains the pure PyTorch training (`train_epoch`) and validation (`validate_epoch`) loops, isolating the core mathematical steps from the script setup.
* **`data/`**: Manages all data loading and preprocessing.
  * `datamodule.py`: Contains the `DummyS2SDataset` and PyTorch `DataLoader` logic.
  * `camels_loader.py`, `era5_loader.py`, `hindcast_loader.py`: Reserved for future data extraction and preprocessing logic for specific datasets.
* **`models/`**: Defines the neural network architectures.
  * `s2s_pipeline.py`: Contains `DummyLinearS2S`, a baseline model that flattens multi-dimensional inputs and passes them through an MLP.
  * `spatial.py`, `static.py`, `decoder.py`: Modular architectural components in active development (e.g., spatial feature extractors and sequence decoders).
* **`utils/`**: General helper modules.
  * `losses.py`, `metrics.py`, `transforms.py`: Reserved for custom loss functions, evaluation metrics (e.g., NSE, RMSE), and data normalization transforms.

### 4. Testing (`tests/`)
Contains the `pytest` suite to ensure pipeline stability and verify module behavior.
* `test_dataloaders.py`: Validates that the dataset generators output tensors with the exact dimensions specified in the configuration.
* `test_losses.py`, `test_models.py`: Placeholders for upcoming unit tests verifying model forward passes and loss calculations.

### 5. Outputs (`outputs/` & `multirun/`)
These directories are automatically generated by Hydra. Each execution creates a new timestamped directory (e.g., `outputs/YYYY-MM-DD/HH-MM-SS/`) containing the exact `.hydra/` configuration used and the associated log files, ensuring strict reproducibility for every experiment.

## Running Tests

To run the test suite, ensure your Conda environment is active and execute:
```bash
pytest tests/
```
